# Example team prompts and expected behavior

These illustrate how the skill should behave. Replace the example products and flows with your own when sharing with your team.

## Example 1: Build a product page
Prompt: "Use /customer-experience-excellence to improve the flagship product detail page in this repository. Preserve our components and tokens."
Expected: inspect the actual PDP, product data and design system; identify compatibility, demonstration, proof, cost and CTA clarity; implement focused improvements with responsive/accessible states; run available checks; summarize outcomes and unverified assumptions.

## Example 2: Booking flow review
Prompt: "Use /customer-experience-excellence to review the consultation booking flow. Prioritize mobile friction."
Expected: inspect screens/code and booking states; report severity-ranked issues including timezone, slot availability, error recovery, confirmation and consent; reference files/lines; propose tests.

## Example 3: Membership account
Prompt: "Use /customer-experience-excellence to design a self-service upgrade/downgrade membership experience for our subscription product."
Expected: inspect current billing/account stack; clarify entitlement rules only if unavailable; distinguish immediate vs renewal-date changes, prorations and cancellation; create accessible states; never invent billing API capabilities.

## Example 4: Lead-gen design exploration
Prompt: "Use /customer-experience-excellence to propose three delightful lead-gen journeys for our installed-service offering that qualify customers without a long form."
Expected: provide three differentiated concepts, transparent customer effort and tradeoffs, conversion hypotheses, and an experiment plan; do not pretend to have implemented a prototype.

## Example 5: Pull request critique
Prompt: "Use /customer-experience-excellence to review this PR for UX quality, accessibility and brand consistency."
Expected: review diff and relevant existing patterns; identify only grounded defects and important risks with severity, evidence, fixes and validation; do not invent screenshots or test results.
